# still. — wallpaper studio

Обои Wallhaven в интерьере вашего рабочего стола. Главная страница — векторная сцена по фотографиям: монитор, ноутбук, лампа, гирлянда и предметы на столе. Выбирайте свет, примеряйте обои на экранах, открывайте превью телефона и галерею.

## Быстрый запуск в Docker

Нужны Docker Engine с Compose v2 или Docker Desktop. Из корня проекта:

```bash
docker compose up --build
```

Откройте [http://localhost:8000](http://localhost:8000). Первый запуск скачивает базовые образы и зависимости, поэтому требует интернет. Бэкенд и собранный фронтенд работают в одном контейнере.

Ключ Wallhaven для публичного SFW-поиска не обязателен. При необходимости скопируйте пример настроек и заполните его:

```bash
cp .env.example .env
```

`WALLHAVEN_API_KEY` передаётся только серверу. `PORT` меняет порт на компьютере, например `PORT=8080`. После изменения настроек перезапустите Compose. Файл `.env` не попадает в образ.

```bash
docker compose up -d --build
docker compose logs -f app
docker compose down
```

Проверка сервера:

```bash
curl --fail http://localhost:8000/api/health
```

Healthcheck проверяет сам сервер; доступность внешнего Wallhaven проверяется при поиске.

## Локальная разработка

Рекомендуются Python 3.12 и Node.js 22 с npm. Все Python-зависимости устанавливаются в виртуальное окружение.

В первом терминале из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

Если нужен ключ при локальном запуске, задайте `WALLHAVEN_API_KEY` в окружении процесса сервера. Compose читает `.env` автоматически; локальный запуск uvicorn не требует и не предполагает такого чтения.

Во втором терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно [http://localhost:5173](http://localhost:5173)). Dev-сервер перенаправляет `/api` на `http://127.0.0.1:8000`.

Для локальной проверки production-сборки:

```bash
npm --prefix frontend run build
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

После сборки FastAPI раздаёт `frontend/dist` на порту 8000. Запускайте эту команду после остановки предыдущего процесса на том же порту.

## Проверки

```bash
.venv/bin/python -m pytest backend/tests
npm --prefix frontend run build
docker compose config --quiet
```

Браузерные проверки выполняются при запущенном приложении на порту 8000:

```bash
cd tests/browser
npm ci
npx playwright install chromium
npm test
```

Другой адрес можно задать через `BASE_URL=http://localhost:8001 npm test`. Браузерные тесты проверяют подборки, фильтры, избранное, телефонное превью, скачивание, ошибки и мобильную вёрстку. Изображения и ответы Wallhaven в них подменяются локальными данными; живое API проверяется отдельно.

Тесты API используют подменённые ответы внешнего сервиса, поэтому не требуют ключа и не зависят от текущей коллекции Wallhaven. Отчёт по контейнеру и ограничениям проверки находится в [docs/docker-validation.md](docs/docker-validation.md).

## Устройство проекта

- `frontend/` — React, TypeScript и Vite; интерактивная SVG-сцена, просмотр телефона и галерея.
- `backend/` — FastAPI; проверка фильтров, запросы Wallhaven, ограниченный кэш в памяти и раздача production-фронтенда.
- `requirements.txt` — зависимости сервера; `requirements-dev.txt` — зависимости для разработки и тестирования.
- `Dockerfile` — три этапа: сборка интерфейса, Python venv, runtime без Node.js и инструментов сборки фронтенда.
- `compose.yaml` — запуск с непривилегированным пользователем, read-only файловой системой и healthcheck.

Исходные изображения остаются на серверах Wallhaven. Сервис использует только SFW-выдачу. Публичное API описано в [документации Wallhaven](https://wallhaven.cc/help/api). При скачивании и использовании учитывайте права автора изображения; ссылка на источник доступна в интерфейсе.

## Ограничения

- Для новых подборок и загрузки изображений нужен доступ к Wallhaven. Таймаут, блокировка провайдером или ограничение частоты запросов могут прервать выдачу; интерфейс показывает ошибку и позволяет повторить запрос.
- Учётных записей и общей базы данных нет. Избранное и настройки хранятся в текущем браузере; очистка данных браузера удаляет их.
- Кэш сервера живёт в памяти одного процесса и очищается при перезапуске. Несколько экземпляров сервиса имеют независимые кэши.
- Превью телефона показывает кадрирование; скачивается исходный файл обоев.
- Базовые Docker-образы закреплены по версии Node.js/Python, но не по digest. Повторная сборка может получить новые исправления базового образа; полной побайтовой воспроизводимости нет.

Для размещения на публичном домене используйте TLS на reverse proxy перед контейнером. Публикация проекта и настройка домена в локальную сборку не входят.
